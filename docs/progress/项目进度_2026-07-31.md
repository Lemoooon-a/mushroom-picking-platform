# 蘑菇采摘平台当前进度

> 盘点日期：2026-07-31  
> 盘点范围：仓库现有代码、文档、离线测试、STM32 固件构建结果及嵌套固件仓库提交历史。  
> 状态口径：`已验证` 表示仓库中存在对应实现，且有本次可复现测试、构建结果或明确实机记录；`初步完成` 表示主流程代码已具备，但仍缺实机验收、边界测试或系统集成；`待开发` 表示仅有目录、设计或占位说明。

## 1. 技术结论

项目已完成两条基础控制链路的主体搭建，但尚未进入整机协同采摘阶段：

1. **STM32 侧的 Slide、Z 轴运动与归零已经达到初步可用状态。** 两轴具备步进驱动、位置/速度/加速度换算、机器坐标、位置有效性、归零、停止、禁用、故障状态和串口机器协议。Slide 的 StallGuard 无传感器归零及 Z 轴感应开关归零已有实机验证依据，但最终全行程软限位仍未标定，部分异常场景仍需补测。
2. **串口控制接口已经形成较完整文档和代码。** 当前使用 ASCII（American Standard Code for Information Interchange，美国信息交换标准代码）行协议，支持 Slide、Z 轴和吸盘的查询、运动、归零、停止、禁用、故障清除与异步完成事件，并有 Python 参考客户端。
3. **吸盘控制已完成代码级初版，但还不能视为实机闭环完成。** 非阻塞吸附/释放状态机、泵与释放阀互锁、脉宽调制（Pulse Width Modulation, PWM）输出、串口命令和安全关闭路径已经接入且固件可构建；不过相关修改尚未提交，脉宽和时序仍是台架初始值，仓库中也没有真空传感器反馈实现或完整实机验收记录。
4. **瓴控 MG4010E 肩肘关节的进度比“只有运动学解算和零点”更靠前。** 当前已有 CAN（Controller Area Network，控制器局域网）传输层、协议编解码、状态读取、位置命令、软件停止、有限行程关节抽象、逻辑零点/方向/软限位配置、命令行调试工具和平面二旋转关节正逆运动学；本次 105 项离线测试全部通过。
5. **MG4010E 仍停留在“单关节安全控制基础完成、双关节协同未完成”的阶段。** 尚无到位等待、运动超时、双电机协调、轨迹执行、运动学解与实际关节限位联合筛选，也没有与 Slide、Z、末端旋转和吸盘组成整机动作链。

## 3. STM32 固件进度

### 3.1 Slide 与 Z 轴

当前固件已经实现两轴共用的最小运动层，并明确区分机器坐标和上位机工作坐标。底层位置是根据已发 STEP 脉冲推算的开环命令位置，不是编码器反馈位置。

已确认的能力包括：

- Slide 正方向定义为向左（+Y），Z 正方向定义为向上（+Z）；
- 两轴归零成功并安全回退后，将回退完成位置设置为机器坐标 0；
- 支持 step 与 µm、step/s 与 µm/s、step/s² 与 µm/s² 的整数换算；
- 支持相对运动、绝对机器位置运动、立即停止、禁用、状态查询和故障清除；
- 只有 `homed=1` 且 `position_valid=1` 时，绝对运动和机器软限位才可信；
- 上电、归零失败、普通 Slide 堵转或显式禁用后，位置会被标记为无效；
- 上电默认不运动、不自动归零，两轴驱动保持禁用。

当前两轴软限位都暂设为 `0..200 step`，只是本阶段的保守安全范围，不是最终机械行程：

| 轴 | 归零方式 | 归零后回退 | 当前临时软限位 | 实机依据 |
| --- | --- | ---: | ---: | --- |
| Slide | StallGuard + DIAG1 快停 | 200 step | `0..200 step`，约 `0..4375 µm` | 文档明确记录参数和流程已实机确认，相关固件提交也标记为 verified |
| Z | PD2 低有效感应开关 | 200 step | `0..200 step`，约 `0..625 µm` | 文档记录了开关释放距离实测数据，相关提交标记为已验证 Z endstop homing |

仍需注意：

- Z_STOP 当前只进入归零状态机，普通位置运动暂不响应该输入；
- Slide 只有一个 StallGuard 端点参考，预回退需要机构始终保留安全空间，否则无法保证任意上电位置都能安全归零；
- Slide 的无触发、超时、用户中止和回退阶段重复触发等场景在文档中仍列为“还必须测试”；
- 必须实测两轴完整安全行程后再替换临时软限位。

### 3.2 串口机器协议

固件分支 `refactor/rebuild-motion-layer` 已在 2026-07-28 提交基础串口协议。协议以一行一帧传输，使用 sequence 关联命令与完成事件：

```text
@<seq> <cmd> [args...]
=<seq> OK | ERR <error_code>
!<seq> DONE | ABORT | FAULT ...
```

当前轴控制命令包括 `QS`、`MR`、`MA`、`HM`、`ST`、`DI`、`EN`、`SA`、`CF` 和 `QH`；吸盘扩展包括 `SQ`、`SU`、`SR` 和 `SX`。运动、归零、吸附和释放均为非阻塞命令，接受命令与实际完成通过不同消息报告。

Python 参考客户端 `firmware/stm32_motion_controller/host/examples/motion_serial_example.py` 已实现序号管理、mm 到 µm 转换、同步/异步消息区分、状态查询、归零、绝对移动和吸盘操作。

### 3.3 吸盘控制

当前工作树新增了独立 `vacuum_control` 状态机及 STM32 端口适配，已接入 App 主循环和串口协议。主要行为为：

- 吸附前先关闭泵和释放阀，等待 30 ms 互锁切换，再开启泵；
- 释放前先关闭两路输出，等待 30 ms，再开启释放阀；
- 默认释放 500 ms，随后自动关闭；
- 禁止泵与释放阀同时开启；
- 初始化和故障路径尽力把两路输出关闭；
- 泵使用 `PA7/TIM3_CH2`，释放阀使用 `PB0/TIM3_CH3`。

当前限制：

- 吸盘相关 13 个文件变更/新增仍在嵌套固件仓库工作树中，尚未形成提交；
- `800 µs / 2300 µs` PWM 脉宽、30 ms 切换延时和 500 ms 释放时长均注明为初始台架参数，不是最终标定值；
- 没有真空开关或压力传感器，因此 `DONE V 1` 只表示泵已成功开启，不代表已经吸住蘑菇；
- 紧急或严重故障时应关闭全部输出还是主动泄压，代码中仍保留安全策略待定项；
- 当前没有吸盘状态机的独立单元测试或仓库内实机测试记录。

## 4. MG4010E 肩肘关节进度

### 4.1 已形成的代码链路

MG4010E 当前已经具备以下分层：

```text
CanMotorBus
  → mg4010_protocol
  → MG4010Driver
  → CanRotaryJoint
  → Planar2RKinematics（当前仍是独立纯计算层）
```

各层当前能力：

- `CanMotorBus`：支持 `gs_usb` 和 SocketCAN、共享总线锁、旧帧清理、超时、重试、标准帧校验、请求/应答 ID 匹配和同 ID 应答兼容；
- `mg4010_protocol`：支持 `0x94` 单圈绝对位置、`0x92` 多圈坐标、`0x9A` 故障/运行状态、`0x9C` 速度/温度/电流/编码器状态、`0xA4` 多圈绝对位置命令 2 和 `0x81` 软件停止；
- `MG4010Driver`：把 8 字节数据域封装为电机级接口；位置命令结果无法确认时会尽力发送一次 `0x81`；
- `CanRotaryJoint`：将电机侧角度换算为输出轴弧度，处理 36:1 减速比、方向、软件零点、有限行程唯一解、软限位、速度限制、稳定初始化和运动前状态检查；
- 调试脚本：支持只读参数查询、离线 dry-run、按关节名加载配置以及显式允许的实机小角度运动；
- `Planar2RKinematics`：支持肩肘平面正运动学、两支逆解、不可达目标判断、伸直/折叠奇异点和数值边界处理。

### 4.2 当前肩肘标定值

仓库配置和文档都将以下数值描述为当前上机测量值：

| 关节 | CAN ID | 减速比 | 逻辑零点对应输出轴绝对角 | 逻辑方向 | 逻辑软限位 | 最大逻辑速度 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| shoulder | 1 | 36:1 | `100°` | `+1` | `-60° .. +70°` | `50°/s` |
| elbow | 2 | 36:1 | `158°` | `-1` | `-152° .. +152°` | `50°/s` |

这些值实现的是**软件逻辑零点**，没有执行电机 `0x19`，也没有写入电机只读存储器（Read-Only Memory, ROM）。关节位置真值使用 `0x94` 单圈绝对位置；`0x92` 只作为当前上电周期内构造 `0xA4` 目标的多圈坐标，不能持久化为机械零点。

对标定进度的判断为“初步完成”，而不是“最终验收”，原因是：

- 配置、测试和说明相互一致，肩肘零点映射与肘关节跨 `0°/360°` 反向解析均有离线测试；
- 文档记录了 `0x92` 跨重启变化、同 ID 应答和 `0xA4` 速度换算等实测结论；
- 但 `docs/calibration/` 目前只有占位文件，没有原始测量日期、工装姿态、重复测量结果、照片或验收签字，无法从仓库独立复核实机标定过程。

### 4.3 运动学进度

肩肘运动学当前只覆盖选择顺应性装配机器人手臂（Selective Compliance Assembly Robot Arm, SCARA）的 XY 平面 2R 模型：

- 坐标定义为 x 向前、y 向左、z 向上；
- 肩角相对全局 +x，肘角相对第一连杆；
- 支持正解和全部主值逆解；
- 逆解不直接访问 CAN，也不发送电机命令；
- 逆解当前不会使用肩肘实际软限位筛选分支。

因此，“输入目标 XY → 选取合法逆解 → 下发肩肘目标 → 等待双关节到位 → 处理超时/故障”这条完整路径尚未实现。

### 4.4 MG4010E 当前缺口

`host/motion/` 和 `host/tasks/` 仍是占位目录。当前明确缺少：

1. 单关节到位等待和稳定窗口判断；
2. 运动超时、运行中故障检测和统一停止；
3. 肩肘双关节命令协调与轨迹执行；
4. 运动学解按当前肩肘软限位、碰撞和连续性进行筛选；
5. 实际连杆长度、安装偏移和末端工具中心点的统一配置；
6. MG4010E 与 Slide、Z、末端旋转轴和吸盘的统一关节/执行器接口；
7. 双电机同总线长时间运行、异常应答、断电重启和急停恢复的实机验收记录。

## 6. 版本与可追溯性风险

当前仓库存在两层 Git 状态：

- 根仓库 `main` 尚无任何提交；除 `.gitignore` 已暂存外，项目代码和文档均为未跟踪内容；
- `firmware/stm32_motion_controller` 是独立嵌套 Git 仓库，当前分支为 `refactor/rebuild-motion-layer`，已有 12 个提交；
- 固件基础串口协议最后一个已有提交为 `905a9e2 feat(protocol): add ASCII serial interface for host motion control`；
- 吸盘功能、吸盘协议扩展、TIM3 配置和 Python 示例仍是嵌套固件仓库中的未提交修改。

这意味着上位机 MG4010E 代码、标定配置和本进度文档目前都没有提交历史，无法可靠追踪“何时完成、由谁验证、对应哪次实机状态”。在继续系统集成前，应先建立可回退的版本基线。

## 7. 建议的下一阶段顺序

### P0：先固定当前可用基线

1. 确认嵌套固件仓库采用 Git submodule、subtree 还是普通目录，避免根仓库提交时遗漏固件内容；
2. 将 MG4010E 当前实现、肩肘标定值、STM32 已验证提交和吸盘未提交修改分别形成清晰提交；

### P1：完成吸盘和 MG4010E 的实机验收

1. 台架验证吸盘泵/阀 PWM 极性、开关脉宽、切换延时、释放时长和故障安全状态；

3. 对肩、肘分别执行断电重启位置复核、低速小角度正反向运动、零点回归、软限位拒绝和 `0x81` 停止测试；
4. 两个电机共用一个 `CanMotorBus`，验证交错查询、连续命令、超时、错误帧和断连恢复。

### P2：补齐肩肘协调层

1. 实现到位等待、稳定时间窗、超时、故障轮询和失败时双关节停止；

3. 优先实现低速点到点双关节协调，再决定是否需要时间同步轨迹和插补；
4. 增加“目标 XY → 逆解 → 关节命令 → 到位确认”的离线集成测试和受控实机测试。

### P3：进入整机动作链

1. 统一 Slide、shoulder、elbow、Z、末端旋转和吸盘的状态与停止接口；
2. 建立相机、滑轨、SCARA 基座、培养槽和工具中心点之间的坐标变换；
3. 实现接近、下探、吸附确认、抬升、搬运、释放和失败恢复的采摘状态机；
4. 最后再进行视觉目标接入和连续采摘节拍优化。

## 8. 进度定位

当前最准确的阶段描述是：

> **底层执行器与单关节控制基础已基本搭好，STM32 Slide/Z 已达到初步可用，MG4010E 肩肘已完成协议、单关节安全控制、初步标定和独立运动学；下一关键里程碑是吸盘实机闭环与肩肘双关节协调，而不是直接进入完整采摘流程。**
