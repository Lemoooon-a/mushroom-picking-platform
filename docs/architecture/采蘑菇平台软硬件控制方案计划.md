# 采蘑菇平台软硬件控制方案计划

## 1. 项目目标

本项目计划搭建一套基于滑轨 SCARA 机械臂的采蘑菇平台，完成蘑菇目标识别、机械臂定位、吸盘采摘和搬运放置等基本功能。

系统采用以下执行机构：

| 关节 | 机械形式 | 执行器 | 控制方式 |
| --- | --- | --- | --- |
| 滑轨轴 | 水平直线运动 | 步进电机 | STM32 或运动控制板 |
| 肩关节 | SCARA 第一旋转关节 | 瓴控 MG4010E-i36 | CAN 总线 |
| 肘关节 | SCARA 第二旋转关节 | 瓴控 MG4010E-i36 | CAN 总线 |
| Z 轴 | 垂直直线运动 | 步进电机 | STM32 或运动控制板 |
| 末端旋转轴 | 吸盘和 RealSense 旋转 | 总线舵机 | USB 转总线控制板 |

整个机构可抽象为五个关节：

\[
q=[s,\theta_1,\theta_2,z,\theta_w]
\]

其中：

- \(s\)：滑轨位置；
- \(\theta_1\)：肩关节角度；
- \(\theta_2\)：肘关节角度；
- \(z\)：Z 轴高度；
- \(\theta_w\)：末端旋转角度。

---

## 2. 总体实施思路

第一阶段以功能实现和快速调试为主要目标，不构建过于复杂的工业控制架构。

计划采用轻量化的混合控制方案：

- 上位机负责视觉处理、坐标变换、运动学解算、任务流程和总线设备控制；
- STM32 或专用运动控制板负责两个步进电机、限位开关、吸盘和安全输入输出；
- CAN 关节电机和末端总线舵机暂时由上位机直接控制；
- 后期如有更高实时性或产品化需求，再逐步将部分控制功能迁移到统一下位机。

总体结构如下： 
<div style="page-break-after: always; break-after: page;"></div>

```text
                         ┌────────────────────┐
                         │      上位机 PC      │
                         │                    │
                         │ RealSense视觉处理   │
                         │ 坐标变换            │
                         │ 运动学解算           │
                         │ 采摘任务状态机       │
                         └─────────┬──────────┘
                                   │
             ┌─────────────────────┼──────────────────────┐
             │                     │                      │
          USB-CAN              USB/串口               USB/串口
             │                     │                      │

        肩关节、肘关节             │                      │

                                                    限位开关    限位开关
                                                       │
                                                吸盘阀、真空检测
```

## 3. 控制方案选择

### 3.1 上位机直接控制方案

上位机通过以下接口直接控制各执行器：

- USB-CAN 控制两个 MG4010E-i36 关节电机；
- USB 转总线控制板控制末端舵机；
- USB、串口或网络接口控制步进运动控制板；
- USB 3.x 接口连接 RealSense。

该方案结构简单、开发速度快，适合目前整体运行速度较低的采摘平台。

需要注意，步进电机不宜由 Python 程序通过 USB IO 逐个发送脉冲。USB 调度、操作系统线程调度和串口缓存会导致脉冲间隔不稳定，进而造成振动、丢步或位置误差。

因此，步进控制应采用以下方式之一：

1. 使用能够独立生成 STEP/DIR 脉冲和加减速曲线的运动控制板；
2. 使用 STM32 接收目标位置和速度，由 STM32 在本地生成步进脉冲。

上位机应发送类似以下命令：

```text
MOVE RAIL 350.0 50.0 100.0
MOVE Z 80.0 20.0 50.0
```

而不是通过 USB 逐个产生 STEP 脉冲。

### 3.2 统一 STM32 下位机方案

完整的统一下位机方案可由 STM32 同时管理：

- 两个 CAN 关节电机；
- 两个步进电机；
- 总线舵机；
- 吸盘；
- 限位开关；
- 真空检测；
- 急停；
- 轨迹执行。

该方案实时性和系统一致性更好，但开发内容明显增加，包括多种通信协议、状态管理、轨迹控制和上位机通信协议设计。

对于当前低速原型平台，完整统一下位机带来的收益有限，因此暂不作为第一阶段方案。

### 3.3 推荐方案

第一版系统计划采用轻量 STM32 下位机方案：

#### 上位机负责

- RealSense 数据采集；
- 蘑菇目标识别；
- 相机坐标到机器人坐标转换；
- 滑轨位置选择；
- SCARA 正逆运动学；
- CAN 关节控制；
- 总线舵机控制；
- 采摘任务状态机；
- 状态显示、日志和故障处理。

#### STM32 或运动控制板负责

- 滑轨步进脉冲；
- Z 轴步进脉冲；
- 加减速控制；
- 原点回零；
- 限位开关；
- 吸盘电磁阀；
- 真空压力检测；
- 看门狗；
- 急停和故障停止。

该方案能够控制开发工作量，同时保证步进控制和安全输入输出的可靠性。

## 4. 硬件连接计划

### 4.1 电源系统

计划将动力设备和控制设备分开供电：

```text
交流输入
   │
   ├── 24 V主电源
   │     ├── 两个CAN关节电机
   │     ├── 滑轨步进驱动器
   │     └── Z轴步进驱动器
   │
   ├── DC-DC → 总线舵机额定电压
   │
   └── DC-DC → 5 V控制电源
         ├── STM32
         ├── 传感器
         └── IO电路
```

电源设计中需要重点考虑：

- 两个 CAN 关节电机的峰值电流；
- 步进电机启动和堵转电流；
- 总线舵机启动电流；
- 电磁阀和气泵等感性负载；
- 控制电源与动力电源之间的干扰；
- 急停时的动力切断方式。

RealSense 计划直接连接上位机 USB 3.x 接口，避免使用质量不稳定的 USB Hub。

### 4.2 CAN 总线连接

两个 MG4010E-i36 关节电机通过同一条 CAN 总线连接：

```text
USB-CAN
   │
CAN_H / CAN_L / GND
   │
肩关节电机
   │
肘关节电机
```

实施时需要：

- 为两个电机设置不同 CAN ID；
- 采用总线式串联连接，避免星形分叉；
- 在 CAN 总线两端配置 120 Ω终端电阻；
- 使用双绞线连接 CAN_H 和 CAN_L；
- 尽量将 CAN 信号线与电机动力线分开布置；
- 确认 USB-CAN 和电机之间的参考地连接方式；
- 优先使用带隔离功能的 USB-CAN。

### 4.3 步进电机连接

两个步进轴采用 STEP/DIR/ENABLE 控制：

```text
STM32或运动控制板
      │
 STEP / DIR / ENABLE
      │
   步进驱动器
      │
    步进电机
```

滑轨和 Z 轴均计划配置：

- 原点限位开关；
- 末端限位开关；
- 软件最小位置；
- 软件最大位置；
- 驱动器使能控制；
- 急停输入；
- 回零流程。

由于普通步进电机没有位置反馈，系统上电后必须执行回零。发生碰撞、堵转或疑似丢步后，也需要重新回零。

对于垂直 Z 轴，还需要评估断电下坠风险，可考虑：

- 带抱闸电机；
- 自锁丝杠；
- 配重；
- 气弹簧；
- 机械制动结构。

### 4.4 吸盘和真空系统

吸盘系统计划由 STM32 控制电磁阀或真空泵。

连接方式如下：

```text
STM32 IO
   │
MOSFET或继电器驱动模块
   │
电磁阀或真空泵
```

STM32 IO 不应直接驱动电磁阀或气泵。

系统计划增加真空压力开关或真空传感器，用于判断蘑菇是否成功吸附，避免只根据吸盘开启状态推测采摘是否成功。

### 4.5 急停和安全回路

急停功能不依赖上位机软件单独实现。

急停触发后，应优先切断：

- CAN 关节电机动力或使能；
- 步进驱动器动力或使能；
- 吸盘执行输出。

上位机可以保持供电，用于显示故障状态、保存日志和执行故障恢复。

## 6. 硬件驱动层计划

硬件驱动层只负责具体设备通信，不处理运动学和采摘任务。

计划实现以下驱动模块：

```text
CanMotorDriver
StepperControllerDriver
BusServoDriver
VacuumIODriver
RealSenseDriver
```

各驱动模块主要负责：

- 打开和关闭设备；
- 发送底层通信数据；
- 接收设备反馈；
- 数据帧校验；
- 超时检测；
- 重连处理；
- 编码器、脉冲和协议单位转换；
- 故障码读取。

驱动层不直接处理蘑菇坐标，也不决定关节目标位置。

## 7. 关节抽象层计划

所有执行器计划统一抽象为关节，使上层不需要关心 CAN 数据帧、步进脉冲或舵机寄存器。

每个关节提供统一接口：

```python
joint.enable()
joint.disable()
joint.home()
joint.move_to(position, velocity, acceleration)
joint.get_position()
joint.is_moving()
joint.stop()
joint.get_fault()
```

关节层统一处理：

- 单位转换；
- 转动方向；
- 零位偏置；
- 位置限位；
- 速度限制；
- 加速度限制；
- 通信故障；
- 状态缓存。

每个关节计划配置以下通用参数：

```text
name
joint_type
direction
zero_offset
min_position
max_position
max_velocity
max_acceleration
```

步进关节额外配置：

```text
steps_per_revolution
microstep
screw_pitch
steps_per_mm
home_direction
home_speed
```

CAN 关节额外配置：

```text
can_id
can_bitrate
gear_ratio
motor_zero_offset
position_command_range
```

上层统一使用：

- 直线关节：mm 或 m；
- 旋转关节：rad。

## 8. 运动学计划

### 8.1 正运动学

设滑轨沿机器人 X 方向运动，两个 SCARA 连杆长度分别为 \(L_1\) 和 \(L_2\)。

末端平面位置为：

\[
x=s+L_1\cos\theta_1+L_2\cos(\theta_1+\theta_2)
\]

\[
y=L_1\sin\theta_1+L_2\sin(\theta_1+\theta_2)
\]

末端方向为：

\[
\phi=\theta_1+\theta_2+\theta_w
\]

Z 轴位置根据实际机械安装方向转换为末端高度。

### 8.2 SCARA 逆运动学

给定滑轨位置 \(s\) 后，首先计算目标点相对于 SCARA 底座的位置：

\[
x_r=x-s
\]

然后计算：

\[
c_2=
\frac{x_r^2+y^2-L_1^2-L_2^2}
{2L_1L_2}
\]

\[
\theta_2=
\operatorname{atan2}
\left(
\pm\sqrt{1-c_2^2},c_2
\right)
\]

\[
\theta_1=
\operatorname{atan2}(y,x_r)
-
\operatorname{atan2}
\left(
L_2\sin\theta_2,
L_1+L_2\cos\theta_2
\right)
\]

末端旋转轴角度为：

\[
\theta_w=\phi-\theta_1-\theta_2
\]

逆运动学通常存在左肘和右肘两组解。软件计划根据以下条件选择：

- 是否超过关节限位；
- 是否接近奇异位置；
- 是否存在机械碰撞风险；
- 是否与当前姿态接近；
- 是否需要过大的滑轨移动。

## 9. 滑轨冗余处理计划

滑轨和两个 SCARA 关节都能够改变末端 X 方向位置，因此同一个末端目标可能对应多组关节解。

第一版不使用复杂优化器，采用一维候选搜索：

1. 在滑轨允许范围内生成多个候选位置；
2. 对每个滑轨候选位置计算 SCARA 逆解；
3. 删除无解或超过限位的结果；
4. 计算每组解的代价；
5. 选择代价最低的目标关节组合。

代价函数可采用：

\[
J =
w_s|s-s_{\text{current}}|
+w_q\|q-q_{\text{current}}\|
+w_lP_{\text{limit}}
+\frac{w_g}{|\sin\theta_2|+\varepsilon}
\]

该方法主要用于：

- 减少滑轨移动距离；
- 减少关节转动；
- 避免接近关节限位；
- 避免手臂完全伸直或完全折叠；
- 提高运动连续性。

由于平台运行速度较慢，一维搜索的计算量可以接受。

## 10. 运动控制计划

第一阶段采用点到点运动，不立即实现复杂的五轴同步轨迹规划。

计划提供以下上层接口：

```python
robot.home()
robot.move_joint(joint_targets)
robot.move_pose(x, y, z, yaw)
robot.set_vacuum(True)
robot.stop()
```

`move_pose()` 内部执行流程如下：

```text
目标笛卡尔位姿
    ↓
选择滑轨位置
    ↓
SCARA逆运动学
    ↓
生成五个关节目标
    ↓
检查关节限位和工作空间
    ↓
发送至各执行器
```

第一版采摘动作采用分阶段执行：

1. Z 轴升到安全高度；
2. 移动滑轨；
3. 移动肩关节和肘关节；
4. 调整末端旋转轴；
5. Z 轴下降；
6. 开启吸盘；
7. 检查真空状态；
8. Z 轴上升；
9. 移动至收集位置；
10. 关闭吸盘。

该方式不依赖严格的实时同步，便于调试和故障定位。

## 11. RealSense 和吸盘坐标计划

RealSense 和吸盘固定在末端旋转平台上，属于眼在手上结构。

计划定义以下坐标系：

```text
world
rail_base
scara_base
link1
link2
wrist
camera
tcp
```

其中：

- `camera` 为 RealSense 坐标系；
- `tcp` 为吸盘工具中心点坐标系；
- `wrist → camera` 为固定变换；
- `wrist → tcp` 为固定变换。

RealSense 识别得到蘑菇在相机坐标系中的位置 \(p_C\)，通过当前关节状态和相机外参转换为机器人基座坐标：

\[
p_B=T_B^C(q)p_C
\]

然后将机器人坐标系中的目标位置输入逆运动学模块。

系统需要完成以下标定：

- 两个 SCARA 连杆长度；
- 滑轨零点；
- 肩关节和肘关节机械零位；
- Z 轴零点；
- 末端舵机零位；
- RealSense 相对于 wrist 的位姿；
- 吸盘 TCP 相对于 wrist 的位姿。

如果末端没有安装滑环，需要限制舵机旋转范围，避免 RealSense 的 USB 线反复扭转。

## 12. 采摘任务状态机计划

采摘流程计划使用简单有限状态机实现：

```text
IDLE
  ↓
HOMING
  ↓
WAIT_TARGET
  ↓
COMPUTE_TARGET
  ↓
MOVE_ABOVE_TARGET
  ↓
DESCEND
  ↓
VACUUM_ON
  ↓
CHECK_GRASP
  ↓
LIFT
  ↓
MOVE_TO_BIN
  ↓
VACUUM_OFF
  ↓
RETURN
```

发生异常时统一进入：

```text
FAULT
```

计划监控以下故障条件：

- CAN 电机失联；
- CAN 电机返回故障码；
- 步进轴异常触发限位；
- 运动超时；
- 逆运动学无解；
- 目标超出工作空间；
- 真空建立失败；
- 急停触发；
- STM32 看门狗超时。

任务层只决定下一步动作，不直接操作 CAN 数据帧或步进脉冲。

## 15. 第一版系统边界

第一版系统计划实现：

- 五个关节的统一控制；
- 滑轨和 Z 轴自动回零；
- SCARA 正逆运动学；
- 滑轨冗余位置选择；
- RealSense 坐标转换；
- 吸盘控制和真空检测；
- 基本采摘状态机；
- 限位、急停、超时和通信故障处理。

第一版暂不实现：

- 五轴严格同步插补；
- 高速连续轨迹规划；
- 复杂碰撞检测；
- 动力学控制；
- CANopen 完整协议栈；
- ROS 2 Control 和 MoveIt 集成；
- 复杂任务调度；
- 完整工业控制器架构。

后续可以根据运行效果，再决定是否增加同步轨迹、视觉伺服、碰撞检测或统一 STM32 下位机。

## 16. 方案结论

本项目第一阶段计划采用功能优先的轻量控制结构：

> 上位机负责 RealSense 视觉、坐标变换、滑轨位置选择、SCARA 逆运动学、CAN 关节控制、末端舵机控制和采摘任务流程；STM32 或运动控制板负责两个步进轴、限位开关、吸盘、真空检测、急停和看门狗。

所有执行器在软件中统一抽象为关节。上层只使用位置、速度、加速度和状态接口，不直接处理 CAN 数据帧、步进脉冲或舵机寄存器。

该方案能够以较小的开发工作量实现完整采摘功能，同时保留后续向统一下位机、ROS 2 或更复杂轨迹控制扩展的空间。
